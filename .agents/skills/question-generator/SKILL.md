# Workshop Question Generator Skill

## توضیح

این Skill برای تولید **سؤالات خلاقانه، شهودی و تعاملی** برای کارگاه‌های آموزشی است. برخلاف تولیدکننده rule-based (`scripts/generate-questions.mjs`)، این Skill از توانایی خلاقانه LLM برای طراحی سؤالات استفاده می‌کند که:
- با محتوای واقعی هر بخش هماهنگ هستند
- سطوح مختلف شناختی (بلوم) را پوشش می‌دهند
- شرکت‌کنندگان را به تفکر، بحث و خلاقیت دعوت می‌کنند
- برای کارگاه عملی و تعاملی مناسب هستند (نه آزمون)

## نحوه استفاده

وقتی کاربر می‌خواهد سؤالات کارگاه تولد کنید:

```
«سؤالات کارگاه [شماره/نام] را با LLM تولید کن»
```

یا

```
«برای این کارگاه سؤال خلاقانه بساز»
```

## مراحل اجرا

### مرحله ۱: خواندن منابع

**حتماً** این فایل‌ها را بخوانید:

1. **محتوای کارگاه**: فایل `workshops/workshop-*.md` (کاربر مشخص می‌کند کدام کارگاه)
2. **اصول سؤال تعاملی**: `knowledge/presentation/interactive-questions.md`
3. **بلوم و سطوح شناختی**: `knowledge/pedagogy/clil/bloom-integration.md`
4. **فعالیت‌های CLIL**: `knowledge/pedagogy/clil/activities.md`
5. **ارزیابی CLIL**: `knowledge/pedagogy/clil/assessment.md`
6. **فرمت خروجی**: `workshop-infra/scripts/generate-questions.mjs` (برای دیدن ساختار JSON)

### مرحله ۲: استخراج بخش‌ها

از محتوای کارگاه، بخش‌ها را استخراج کنید:

- **فرمت ۱**: `#### بخش ۱: عنوان` (در کارگاه‌هایی با `### جلسه`)
- **فرمت ۲**: `### بخش ۱: عنوان` (در کارگاه‌هایی بدون جلسه)

برای هر بخش، این اطلاعات را استخراج کنید:
- عنوان بخش
- خلاصه محتوا (۲-۳ جمله اول)
- نوع فعالیت (بازی، بحث، تمرین، مفهوم)
- اسلایدهای مرتبط (اگر ذکر شده)

### مرحله ۳: طراحی سؤالات

برای هر بخش، **۱-۳ سؤال** طراحی کنید با رعایت این اصول:

#### الگوی طراحی

```
هر بخش = حداقل ۱ سؤال بازتابی + حداقل ۱ سؤال چالشی/خلاقانه

بخش‌های کوتاه (۲-۵ دقیقه) = ۱ سؤال
بخش‌های متوسط (۵-۱۰ دقیقه) = ۱-۲ سؤال
بخش‌های بلند (۱۰+ دقیقه) = ۲-۳ سؤال
```

#### انواع سؤال (از فایل دانش)

هر بخش باید ترکیبی از این باشد:
- **بازتابی**: دعوت به تجربه شخصی
- **سناریویی**: موقعیت فرضی
- **چالشی**: به چالش کشیدن تفکر
- **ارتباطی**: اتصال به تجربه قبلی
- **خلاقانه**: تولید ایده جدید
- **مشارکتی**: تعامل با دیگران

#### سطوح بلوم

در کل کارگاه، تنوع سطوح بلوم رعایت شود:
- دانش/فهم: ۲۰٪
- کاربرد/تحلیل: ۴۰٪
- ارزیابی/خلق: ۴۰٪

#### قوانین طلایی

1. **باز باشد**: نه بله/خیر
2. **شخصی باشد**: به کار شرکت‌کننده مربوط شود
3. **بی‌قضاوت باشد**: نه سؤال امتحانی
4. **قابل فهم باشد**: در ۵ ثانیه
5. **قابل پاسخ باشد**: در ۲-۳ جمله

### مرحله ۴: تولید خروجی

خروجی را در همان فرمت `generate-questions.mjs` بنویسید:

```json
{
  "workshop": "workshop-1-ai-concepts",
  "generatedAt": "2025-...",
  "sections": [
    { "id": "s1_sec1", "session": 1, "order": 1, "title": "...", "questionCount": 2 }
  ],
  "questions": [
    {
      "id": "s1_sec1_q1",
      "sectionId": "s1_sec1",
      "order": 1,
      "text": "سؤال خلاقانه...",
      "type": "text"
    }
  ],
  "survey": [
    {
      "id": "survey_q1",
      "order": 1,
      "text": "...",
      "type": "rating",
      "options": ["۱", "۲", "۳", "۴", "۵"]
    }
  ]
}
```

### مرحله ۵: نوشتن فایل

خروجی را در فایل زیر بنویسید:

```
workshops/<workshop-name>-questions.json
```

و کاربر را از مسیر فایل آگاه کنید.

## نمونه خروجی

### ورودی (بخش از کارگاه ۱):

```
#### بخش ۲: یک صبح با دستیار هوشمند (۲ تا ۵ دقیقه)
سناریوی صبح: ایمیل خوانده شد (ابزار)، طرح تطبیق داده شد (دانش)، هشدار مهلت (مهارت)
```

### خروجی (سؤالات خلاقانه):

```json
[
  {
    "id": "s1_sec2_q1",
    "sectionId": "s1_sec2",
    "order": 1,
    "text": "در این سناریو، کدام بخش را یک جستجوی ساده می‌توانست انجام دهد؟ چرا گفتیم هیچ‌کدام؟",
    "type": "text"
  },
  {
    "id": "s1_sec2_q2",
    "sectionId": "s1_sec2",
    "order": 2,
    "text": "خودتان یک سناریوی مشابه از یک روز کاری‌تان بنویسید: کجا از ابزار استفاده شد؟ کجا دانش؟ کجا مهارت؟",
    "type": "text"
  }
]
```

## سؤالات نظرسنجی پایانی

همیشه ۶ سؤال استاندارد بسازید:

| # | نوع | سؤال |
|---|-----|------|
| ۱ | rating | به کل کارگاه چه امتیازی می‌دهید؟ (۱-۵) |
| ۲ | text | کدام بخش برایتان جذاب‌تر بود؟ |
| ۳ | text | کدام بخش برایتان کاربردی‌تر بود؟ |
| ۴ | choice | آیا احساس می‌کنید هوش مصنوعی دیگر جادویی نیست؟ |
| ۵ | text | چه چیزی بیشتر می‌خواستید یاد بگیرید؟ |
| ۶ | text | پیشنهاد شما برای بهبود چیست؟ |

## چک‌لیست کیفیت

قبل از تحویل، این موارد را بررسی کنید:

- [ ] هر بخش حداقل ۱ سؤال دارد
- [ ] سؤالات باز هستند (نه بله/خیر)
- [ ] سؤالات شخصی‌سازی شده‌اند
- [ ] تنوع سطوح بلوم رعایت شده
- [ ] سؤالات با محتوای واقعی بخش هماهنگ‌اند
- [ ] سؤالات بی‌قضاوت هستند
- [ ] سؤالات قابل فهم و پاسخ هستند
- [ ] نظرسنجی پایانی کامل است

## تفاوت با generate-questions.mjs

| ویژگی | rule-based | LLM-based (این Skill) |
|-------|-----------|----------------------|
| خلاقیت | محدود به الگوها | بالا |
| هماهنگی با محتوا | عنوان‌محور | عمیق |
| تنوع | محدود | بالا |
| سازگاری | همیشگی | متغیر |
| نیاز به LLM | نه | بله |
| سرعت | سریع | کندتر |

**استفاده**: برای کارگاه‌های مهم و تعاملی → LLM. برای پیش‌نویس سریع → rule-based.
