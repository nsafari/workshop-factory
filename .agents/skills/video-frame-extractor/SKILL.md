# Video Frame Extractor Skill

## توضیح
این Skill یک ویدیوی یوتیوب یا اپارات، **یا یک فایل محلی** را می‌گیرد، بخش‌های مهمش را شناسایی می‌کند و برای هر بخش مجموعه‌ای فریم استخراج و به‌شکل پوشه‌ی مستندشده ذخیره می‌کند: توضیح هر بخش، README اصلی و ترنسکریپت (در صورت وجود).

**پیش‌فرضِ خروجی: `study/frames/<video_slug>/`** — تا فریم‌ها در یکجا با فایل‌های مستند خودآموز (ساخته‌شده با مهارت `self-study-generator`) بمانند. اگر کاربر جای دیگری خواست، `--out` را عوض کنید.

ابزار اصلی، اسکریپت `scripts/yt_frames.py` همین مهارت (مسیر کامل: `.agents/skills/video-frame-extractor/scripts/yt_frames.py`) است. از یک لینک یوتیوب/اپارات **یا یک مسیر فایل محلی** استفاده می‌کند و فریم‌ها را با ffmpeg و با نامِ زمانِ دقیق استخراج می‌کند. برای لینک‌ها با `yt-dlp --download-sections` فقط پنجره‌ی دورِ هر زمان را می‌گیرد (چند مگابایت به‌جای کل ویدیو). برای فایل محلی، نیازی به دانلود نیست و مستقیماً روی فایل کار می‌کند.

## پیش‌نیازها
- `yt-dlp` (یوتیوب و اپارات را به‌طور بومی پشتیبانی می‌کند؛ فقط برای لینک‌ها)
- `ffmpeg` و `ffprobe` (برای استخراج فریم و خواندن متادیتای فایل محلی)
- `python3`

## نحوه استفاده
وقتی کاربر یک لینک ویدیو (یوتیوب/اپارات) **یا مسیر یک فایل ویدیوی محلی** داد و خواست بخش‌های مهم یا لحظه‌های کلیدی‌اش را واکشی کند، این مراحل را دنبال کنید:

### مرحله ۱: جمع‌آوری اطلاعات
۱. **لینک یا فایل ویدیو**: یک لینک یوتیوب/اپارات، **یا** مسیر فایل ویدیوی محلی روی دیسک کاربر.
۲. **فهرست بخش‌ها**: اگر کاربر فهرست زمان و موضوع دارد، بگیرید؛ اگر نه، در مرحله‌ی ۴ از روی ترنسکریپت استخراج می‌شود
۳. **مسیر خروجی** (پیش‌فرض: `study/frames/`)
۴. **تراکم فریم** (پیش‌فرض: هر ۵ ثانیه یک فریم)

### مرحله ۲: متادیتای ویدیو

**برای لینک‌ها (یوتیوب/اپارات):**
```bash
yt-dlp --skip-download --print "%(title)s | %(upload_date)s | %(duration_string)s | %(channel)s | %(view_count)s" "URL"
```

**برای فایل محلی:**
```bash
ffprobe -v error -show_entries format=duration,bit_rate:stream=width,height,r_frame_rate,codec_name -of json "/path/to/video.mp4"
```

- متادیتا را برای README اصلی نگه دارید.
- نام پوشه‌ی خروجی از عنوان ویدیو (یا نام فایل بدون پسوند) ساخته می‌شود؛ مثلاً `study/frames/<video_slug>/`.

### مرحله ۳: گرفتن ترنسکریپت (هرجا شد)

**برای لینک‌ها (یوتیوب/اپارات):**
```bash
yt-dlp --skip-download --write-auto-subs --sub-langs "en.*,fa" --sub-format vtt -o tmp/v.%(ext)s "URL"
```
بعد VTT را به متن ساده با نشانگر `[mm:ss]` تبدیل کنید:

```python
import re
raw = open("tmp/v.en.vtt", encoding="utf-8").read()
cues = [c for c in raw.split("\n\n") if "-->" in c]
items = []
for cue in cues:
    m = re.match(r"(\d+):(\d+):(\d+)\.\d+ -->", cue)
    start = int(m.group(1)) * 3600 + int(m.group(2)) * 60 + int(m.group(3))
    lines = [re.sub(r"<[^>]+>", "", ln).strip() for ln in cue.split("\n")[1:]]
    lines = [ln for ln in lines if ln]
    if lines:
        items.append((start, lines[-1]))
out, prev, last_minute = [], None, None
for start, l in items:
    if l == prev:
        continue
    prev = l
    minute = start // 60
    if not out or minute != last_minute:
        mm, ss = divmod(start, 60)
        out.append(f"[{mm:02d}:{ss:02d}] {l}")
        last_minute = minute
    else:
        out.append(l)
print("\n".join(out))
```

**برای فایل محلی:**
زیرنویس خودکار برای فایل محلی وجود ندارد. دو گزینه:
۱. اک `whisper` نصب باشد (`pip install openai-whisper`)، از آن برای تولید ترنسکریپت استفاده کنید.
۲. از کاربر بخواهید فهرست بخش‌ها را بدهد یا خودتان از روی محتوای ویدیو بخش‌های پیشنهادی تولید کنید.
در این حالت در README اصلی ذکر کنید که ترنسکریپت از whisper تولید شده یا بدون ترنسکریپت واکشی شده‌اند.

اگر ویدیو زیرنویس ندارد (برای اپارات رایج است):

۱. توضیح ویدیو را چک کنید؛ در خیلی از ویدیوهای آموزشی، فهرست بخش‌ها در توضیح آمده است: `yt-dlp --skip-download --print description "URL"`.
۲. اگر نبود، از کاربر زمان تقریبی بخش‌ها را بپرسید.
۳. در این حالت مرحله‌ی «بررسی صحت زمان»ِ مرحله‌ی ۴ انجام نمی‌شود؛ در README اصلی ذکر کنید که فریم‌ها با زمان‌های داده‌شده و بدون امکان راستی‌آزمایی واکشی شده‌اند.

### مرحله ۴: شناسایی بخش‌های مهم
اگر کاربر فهرست بخش داد:

۱. هر جفتِ (زمان، موضوع) را با محتوای ترنسکریپت در همان زمان مقایسه کنید.
۲. اگر ناسازگاری دیدید (رایج است؛ فهرست‌های دست‌ساز اغلب با زمان واقعی ویدیو هم‌خوانی ندارند، به‌خصوص وقتی مدت فرضی ویدیو با واقعیت فرق داشته باشد):
   - جدول «زمان فهرست در برابر محتوای واقعی ویدیو در آن لحظه» را به کاربر نشان دهید.
   - بپرسید: واکشی با زمان‌های درست (پیشنهاد) یا حفظ زمان‌های فعلی.
   - زمان هر بخش را به زمان واقعی همان موضوع در ترنسکریپت تنظیم کنید.

اگر کاربر فهرست نداد:

- ترنسکریپت را بخوانید و ۶ تا ۱۰ بخش پیشنهاد دهید؛ هر بخش با عنوان کوتاه، بازه‌ی زمانی (شروع تا پایان) و توصیف یک تا دو خطی.
- از کاربر تأیید یا اصلاح بخواهید.

### مرحله ۵: واکشی فریم‌ها
برای هر بخش، از ریشه‌ی مخزن:

**لینک:**
```bash
python3 .agents/skills/video-frame-extractor/scripts/yt_frames.py "URL" -t 11:15 -w 45 -i 5 \
  --topic "05_اسلگ_موضوع" --out "study/frames/<video_slug>"
```

**فایل محلی:**
```bash
python3 .agents/skills/video-frame-extractor/scripts/yt_frames.py "/path/to/video.mp4" -t 11:15 -w 45 -i 5 \
  --topic "05_اسلگ_موضوع" --out "study/frames/<video_slug>"
```

اسکریپت به‌طور خودکار تشخیص می‌دهد که ورودی لینک است یا فایل محلی (با بررسی وجود فایل روی دیسک). برای فایل محلی yt-dlp اجرا نمی‌شود.

- `-t`: میانه‌ی بازه‌ی بخش؛ `-w`: نیمی از بازه‌ی واکشی (قبل و بعد از آن زمان). بخش کوتاه (حدود یک دقیقه) → ۳۰، بخش بلند (۲ دقیقه یا بیشتر) → ۴۵.
- پوشه‌ی هر بخش را با شماره‌ی دو رقمی `01_`، `02_`، ... پیشوند بزنید تا ترتیب حفظ شود.
- خروجی: `study/frames/<video_slug>/NN_موضوع/HH_MM_SS.jpg` که نام هر فایل همان زمان دقیقِ ویدیو است.

### مرحله ۶: مستندسازی
۱. **README.md در هر پوشه‌ی بخش**: عنوان موضوع، زمان در ویدیو، تعداد فریم، توصیف ۲ تا ۴ خطیِ بخش (بر اساس ترنسکریپت، نه حدس)، فهرست فریم‌ها.
۲. **README.md اصلی** در `study/frames/<video_slug>/`:
   - جدول اطلاعات ویدیو (عنوان، کانال، سازنده، تاریخ انتشار، مدت، لینک)
   - ساختار فایل‌ها (درخت)
   - جدول بخش‌ها (موضوع، زمان واقعی، تعداد فریم)
   - اگر زمان‌ها اصلاح شده: یادداشت درباره‌ی ناسازگاری اولیه و کاری که شده
   - نحوه‌ی تولید فریم‌ها (اسکریپت و پارامترها)
   - «روش آموزشی ویدیو» (در صورتی که ویدیو آموزشی است): تحلیل این‌که ویدیو چطور تدریس می‌کند؛ از مثال عینی شروع می‌کند یا تعریف انتزاعی، شهود قبل از فرمول می‌آید یا نه، و ...
   - یادداشت مجوز: فریم‌ها اسکرین‌شات از ویدیو برای استفاده‌ی شخصی و آموزشی است
۳. **ترنسکریپت‌ها** در `transcripts/` (در صورت دسترسی):
   - ترنسکریپت زبان اصلی با نشانگر `[mm:ss]` در ابتدای هر پاراگراف (`en.md`، `fa.md`، ...)
   - اگر زبان اصلی فارسی نیست، ترجمه‌ی فارسی کامل هم بگذارید؛ اصطلاحات تخصصی را در بار اول با معادل انگلیسی بنویسید.
   - برای فایل محلی: اگر با whisper ترنسکریپت ساخته شده، در `transcripts/en.md` ذخیره کنید و در README اصلی ذکر کنید که تولید ماشینی است.

### مرحله ۷: راستی‌آزمایی و تمیزکاری
- تعداد فایل هر پوشه‌ی بخش را بشمارید و چند فریم را با `file` یا `ffmpeg -i` اعتبارسنجی کنید.
- فایل‌های موقت (VTT، پوشه‌ی tmp) را پاک کنید.
- بدون درخواست صریح کاربر، پوشه‌ی فریم‌ها را به git ادمیت نکنید (تصاویر سنگین‌اند)؛ در صورت نیاز `study/frames/` را به `.gitignore` اضافه کنید.

## نکات مهم

### فایل محلی (بدون لینک)
وقتی کاربر یک فایل ویدیوی محلی داد (نه لینک):
- اسکریپت خودکار تشخیصداده می‌دهد و yt-dlp اجرا نمی‌شود — نیازی به اینترنت یا احراز هویت یوتیوب نیست.
- متادیتای ویدیو (مدت، ابعاد، کدک) با `ffprobe` خوانده می‌شود.
- مدت ویدیو با ffprobe گرفته می‌شود تا از فریم‌گیری بعد از پایان ویدیو جلوگیری شود.
- زیرنویس خودکار وجود ندارد: یا از کاربر بخواهید بخش‌ها را بدهد، یا با `whisper` ترنسکریپت تولید کنید، یا بدون ترنسکریپت کار را ادامه دهید.
- فایل محلی را در خروجی کپی نمی‌شود؛ فقط فریم‌ها استخراج می‌شوند. اگر کاربر خواست فایل اصلی هم در پوشه‌ی خروجی بماند، به‌صورت دستی کپی کنید.

### بزرگ‌ترین تله: زمان‌های نادرست
فهرست زمان‌هایی که کاربر (یا خلاصه‌سازی دیگر) تهیه کرده، اغلب با محتوای واقعی ویدیو هم‌خوانی ندارد. پیش از واکشی، همیشه با ترنسکریپت راستی‌آزمایی کنید و نتیجه را به کاربر بگویید. واکشیِ اشتباه و اصلاحِ بعدی، چند دقیقه دانلود اضافی برای هر بخش به قیمت تمام می‌شود.

### نگارش فارسی در همه‌ی مستندات
- نیم‌فاصله، اعداد فارسی در متن، «گیومه» برای نقل‌قول، بدون em dash و en dash.
- timestamp ها (مثلاً `00_11_00` یا `10:30`) با اعداد لاتین بمانند: داده‌ی فنی‌اند و با نام فایل‌ها هم‌خوانی دارند.
- پیش از تحویل، lint نگارشی (fa_lint.py در مهارت persian-writing) را روی متن فارسی اجرا کنید؛ هشدارهای داخل بلوک‌های کد و timestamp ها را نادیده بگیرید.

### فقط بخش‌های لازم را دانلود کنید
اسکریپت با `yt-dlp --download-sections` فقط پنجره‌ی دورِ هر زمان را می‌گیرد (چند مگابایت به‌جای کل ویدیو). اگر در فرمتی دانلود بخش پشتیبانی نشود، خودبه‌خود کل ویدیو دانلود می‌شود؛ نتیجه یکسان است.

### اپارات
- yt-dlp اپارات را بومی پشتیبانی می‌کند؛ لینک مستقیم ویدیو کافی است.
- بیشتر ویدیوهای اپارات زیرنویس ندارند؛ از توضیح ویدیو یا فهرست کاربر استفاده کنید.
- برای بخش‌های بلند، فاصله‌ی فریم‌ها را با `-i` بزرگ‌تر کنید تا تعداد فایل کنترل شود.

### تعداد فریم
قاعده‌ی سرانگشتی: هر بخش ۵ تا ۲۰ فریم. پنجره‌ی ۴۰ تا ۹۰ ثانیه با فاصله‌ی ۵ ثانیه برای بیشتر بخش‌ها مناسب است.
